\large The math behind the midterm work}

\vspace{-3em}

\begin{abstract}
\noindent \texttt{gfpop} solves penalized change-point problems under a
user-specified constraint graph, but it imposes the \emph{same} graph at every
time step. This note is the math behind my midterm work: an extension where the
active constraints can depend on the time index through a \emph{rule map}. I
write down the recursion, show it is a strict generalisation (with a constant
rule it reduces to ordinary \texttt{gfpop}), and show that unreachable states
take care of themselves through the infinity arithmetic the solver already has.
I then build two labelled change-point models on top of it: the Gaussian LOPART
model, and an up-down peak model that no current R package expresses. The last
section traces the full dynamic program on a ten-point dataset and checks it
exactly against \texttt{LOPART::LOPART()}. Every number in
Section~\ref{sec:run} comes from an accompanying R script, not by hand.
\end{abstract}

The data clearly step up once, around $t=4$--$5$, and standard penalized
segmentation would find that change from the data alone. What it cannot do is
\emph{use} the labels. \texttt{gfpop} can encode rich structural constraints
through a graph, but the graph is the same at every time step, and a label is
inherently \emph{positional}: it constrains some indices and not others. That
mismatch is the whole problem, and closing it is what this note is about. The
motivating application is genomic peak detection, where experts mark regions of
a coverage profile as containing a peak or not, and the segmentation should
respect those marks.

\section{Background: penalized change-point detection}\label{sec:back-fpop}

Describe a segmentation of $x_{1:n}$ by its vector of segment means
$\mu_{1:n}$, constant on each segment, with a change at $t$ whenever
$\mu_t \neq \mu_{t+1}$. For Gaussian (least-squares) loss the penalized
objective is
\begin{equation}\label{eq:objective}
  \min_{\mu_{1:n}} \ \sum_{t=1}^n (x_t-\mu_t)^2
    \ +\ \lambda \, \bigl|\{\, t< n : \mu_t \neq \mu_{t+1}\,\}\bigr|,
\end{equation}
where the penalty $\lambda>0$ keeps spurious changes out. Optimal partitioning
solves \eqref{eq:objective} with a dynamic program over prefixes, and the trick
in \texttt{gfpop} is to track the best prefix cost \emph{as a function of the
last segment's mean}:
\[
  Q_t(\mu) \;=\; \min\bigl\{\, \text{penalized cost of } x_{1:t}
      \ \text{with last mean } \mu \,\bigr\},
\]
a piecewise quadratic in $\mu$. Only two operations ever happen to it: adding a
data point, $Q(\mu)\mapsto Q(\mu)+(x_t-\mu)^2$ (a quadratic shift), and
committing a change, $Q \mapsto \min_\nu Q(\nu) + \lambda$ (a constant).
Functional pruning keeps just the lower envelope of the candidate quadratics,
and the minimum over $\mu$ is read straight off that envelope
(Figure~\ref{fig:envelope}).

\begin{figure}[h]
\centering

\caption{Two candidate quadratics (dashed) and their lower envelope (solid).

\begin{example}\label{ex:micro}
Take the first three points $x_1,x_2,x_3 = 0.2,-0.1,0.1$ and allow no change:
$Q_3(\mu)=(0.2-\mu)^2+(-0.1-\mu)^2+(0.1-\mu)^2 = 3\mu^2-0.4\mu+0.06$, minimised
at $\bar x=0.0\overline{6}$ with value $\approx 0.047$. That is exactly the
$t=3$, ``normal'' entry of Table~\ref{tab:Q} later on.
\end{example}

\section{Background: the \texttt{gfpop} graph formalism}\label{sec:back-graph}

\begin{definition}[Constraint graph]
A constraint graph is a directed multigraph $G=(S,E)$ on a finite set of states
$S$. Each edge $e=(s\to s')$ has a type in $\{\texttt{null},\texttt{std},
\texttt{up},\texttt{down}\}$ and a penalty $\beta_e\ge 0$. An edge acts on a cost
function by an operator $\Op_e$:
\[
  \Op_{\texttt{null}}(Q)=Q,\qquad
  \Op_{\texttt{std}}(Q)=\min_\nu Q(\nu)+\beta_e,
\]
while \texttt{up}/\texttt{down} additionally impose $\mu'\ge\nu$ / $\mu'\le\nu$
on the committed change.
\end{definition}

Each state carries its own cost function $Q_t^{s}$ at each time, and the edges
are what couple them: for each destination $s'$,
\begin{equation}\label{eq:gfpop-rec}
  Q_{t}^{s'}(\mu) \;=\; \Bigl[\ \min_{e=(s\to s')\in E}\ \Op_e\bigl(Q_{t-1}^{s}\bigr)(\mu)\ \Bigr]
      \;+\; (x_{t}-\mu)^2 ,
\end{equation}
initialised at $t=1$ with $Q_1^{s}(\mu)=(x_1-\mu)^2$ for the start state and
$+\infty$ everywhere else. Figure~\ref{fig:graphs} shows the two standard graphs
everything below builds on.

\section{The extension: time-dependent constraints}\label{sec:extension}

The extension changes exactly one thing in \eqref{eq:gfpop-rec}: the
minimisation no longer has to range over \emph{all} of $E$ at every step.

\begin{definition}[Rule map and active set]\label{def:rule}
Fix $R$ rules. A \emph{rule map} is a function $\Rmap:\{1,\dots,n\}\to\{1,\dots,R\}$.
Each edge $e$ carries a label $r(e)\in\{1,\dots,R\}\cup\{\textsc{na}\}$. The
\emph{active set} at time $t$ is
\[
  E_t \;=\; \{\, e\in E \ :\ r(e)=\textsc{na}\ \text{ or }\ r(e)=\Rmap(t)\,\}.
\]
Edges labelled \textsc{na} are always active; the others switch on only at the
steps their rule selects. The recursion is \eqref{eq:gfpop-rec} with $E$
replaced by $E_t$.
\end{definition}

Another way to see it: there is still one graph, but it gets \emph{sliced} per
step, and at time $t$ the solver only sees the subgraph $(S,E_t)$.
Figure~\ref{fig:timeexp} shows two different slices of the same graph.

Two small facts are what make this safe and cheap to bolt onto the existing
solver, and they are worth stating properly because together they explain why
the C++ changes stayed so small.

\begin{proposition}[Backward compatibility]\label{prop:bc}
If $\Rmap\equiv c$ is constant and every edge has $r(e)\in\{\textsc{na},c\}$,
then $E_t=E$ for all $t$ and the recursion coincides with ordinary
\texttt{gfpop}.
\end{proposition}
\begin{proof}
By Definition~\ref{def:rule}, $e\in E_t$ iff $r(e)=\textsc{na}$ or
$r(e)=\Rmap(t)=c$. Under the hypothesis every edge satisfies one of the two, so
$E_t=E$ for every $t$, and \eqref{eq:gfpop-rec} comes back verbatim. In
particular, supplying no rule at all (every edge \textsc{na}) leaves the output
unchanged. This is the backward-compatibility guarantee, and it is tested
directly.
\end{proof}

\begin{lemma}[Infinity semantics]\label{lem:inf}
Suppose no active edge enters state $s'$ at time $t$, i.e.\ $E_t$ contains no
edge $(\cdot\to s')$. Then $Q_t^{s'}\equiv+\infty$. Moreover both operators map
the constant $+\infty$ function to $+\infty$:
$\Op_{\texttt{null}}(+\infty)=+\infty$ and
$\Op_{\texttt{std}}(+\infty)=\min_\nu(+\infty)+\beta=+\infty$.
\end{lemma}
\begin{proof}
The bracketed minimum in \eqref{eq:gfpop-rec} is over the empty set, hence
$+\infty$; adding $(x_t-\mu)^2$ keeps it there. The operator identities are
immediate. So an unreachable state contributes $+\infty$ to every downstream
minimisation and simply loses; no case distinction is needed anywhere.
\end{proof}

\begin{remark}
Lemma~\ref{lem:inf} is the reason the extension needed \emph{no} change to
\texttt{gfpop}'s constraint operators, including the intricate
\texttt{up}/\texttt{down} code that my proposal had flagged as the main risk.
Skipping an inactive edge just leaves its destination at the $+\infty$ the
solver already initialises, and the existing arithmetic carries it through.
\end{remark}

\section{Model I: LOPART as a 4-rule, 2-state graph}\label{sec:lopart}

LOPART (Hocking \& Srivastava) does Gaussian change-point detection subject to
labels: a positive region must contain exactly one change, a negative region
none. It turns out two states are enough to reproduce it:
$S=\{\texttt{normal},\texttt{noChange}\}$, with four rules, one per label
context. The whole idea sits in the lock state \texttt{noChange}, which records
that the one change a positive region allows has been spent.

The label-to-rule map is simple: unlabelled indices get rule $1$; a positive
region gets rule $2$, except its last index, which gets rule $3$; a negative
region gets rule $4$.

\begin{proposition}[Encoding correctness]\label{prop:lopart}
Under the filmstrip of Figure~\ref{fig:lopart-film}, the feasible state paths are
exactly the segmentations in which every positive region carries exactly one
change and every negative region none.
\end{proposition}
\begin{proof}[Proof sketch]
Follow a path through a positive region, entering in \texttt{normal}. Rule $2$
offers $n\to n$ (\texttt{null}, no change) or the single $n\to c$ (\texttt{std},
one change); once in $c$ the only move is $c\to c$ (\texttt{null}), so at most
one change happens. The region's last index runs under rule $3$, and here is the
key: its only options are $n\to n$ \texttt{std} (force the change if you are
still in $n$) or $c\to n$ \texttt{null} (release if the change was already
taken). There is deliberately no $n\to n$ \texttt{null}, so a path cannot slip
out of the region with zero changes. At most one and at least one: exactly one.
A negative region (rule $4$) offers nothing but $n\to n$ \texttt{null}, so no
change; unlabelled steps (rule $1$) are just the standard model. Running the
construction backwards turns any label-feasible segmentation into a state path,
which gives the bijection.
\end{proof}

\begin{lemma}[Loss identity]\label{lem:loss}
Let $C_{\mathrm{gf}}=\sum_t (x_t-\hat\mu_t)^2$ be \texttt{gfpop}'s reported
residual cost and $L$ be \texttt{LOPART}'s reported \texttt{total\_loss} on the
same fit. Then $C_{\mathrm{gf}} = \sum_t x_t^2 + L$.
\end{lemma}
\begin{proof}
Both implementations minimise the same penalized objective, so they agree on the
optimal segmentation; the only difference is an additive constant in what each
one calls ``loss''. \texttt{LOPART} drops the data-only term $\sum_t x_t^2$,
which does not depend on $\mu$, so its loss is $C_{\mathrm{gf}}-\sum_t x_t^2$.
Rearranging gives the identity. Table~\ref{tab:oracle} checks it numerically:
$\sse = \sumsq - \lopartLossAbs$.
\end{proof}

\section{Model II: up-down with labels (6 rules, 4 states)}\label{sec:updown}

The same mechanism buys a model that, as far as I can tell, no current R
package provides: labelled \emph{peak} detection under an up-down constraint,
where a peak is a rise (\texttt{up}) followed later by a fall (\texttt{down}).
The states are
$\{\texttt{Dw},\texttt{Up},\texttt{noChangeUp},\texttt{noChangeDw}\}$; the two
lock states play the \texttt{noChange} role, one per direction.

Peak-detection labels come in two positive flavours, \texttt{peakStart}
(exactly one \texttt{up}) and \texttt{peakEnd} (exactly one \texttt{down}),
plus \texttt{noPeaks} (flat). Each positive flavour is just LOPART's
\emph{(in, end)} rule pair applied to one direction, so the count works out to
$2+2$ positive rules plus unlabelled plus \texttt{noPeaks}: six. One design
decision makes the end rules well-defined: the forced change lands directly in
the released state ($\texttt{Dw}\to\texttt{Up}$, $\texttt{Up}\to\texttt{Dw}$)
rather than in a lock, so a single index only ever does one job. Getting that
wrong was an easy trap: an end index cannot both fire the change and release
the lock in the same step.

unlabelled it must reproduce \texttt{graph(type="updown")} exactly. Both hold in
the test suite.

\section{Validation summary and outlook}\label{sec:summary}

Three kinds of guarantee back all of this, and each one is an actual test, not
an aspiration. \emph{Backward compatibility} (Proposition~\ref{prop:bc}): run
each labelled graph with an all-unlabelled rule and check it matches the
corresponding standard graph exactly. \emph{Oracle exactness} (Model~I): check
against \texttt{LOPART::LOPART()} for identical changepoints, means and cost up
to the constant of Lemma~\ref{lem:loss}. \emph{Structural invariants}
(Model~II, which has no oracle): check that each label region gets exactly the
number of changes it mandates. All three pass in continuous integration on
Linux, macOS and Windows.

What remains builds on this core: a user-facing vignette with a filmstrip
visualisation of the rule-sliced graph, performance benchmarks, and extending
the labelled models to Poisson loss. But the whole mechanism is just the
mathematics above: a rule map picking an active subgraph per step, with
unreachable states absorbed by the infinity arithmetic the solver already had.
It is done and validated.
